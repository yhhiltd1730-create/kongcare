# 콩케어 단계별 기관 제안 패키지 MASTER v1.0

STATUS: ACTIVE_PREP
DATE: 2026-09-24
PURPOSE: 제안서를 미리 준비하되, Evidence가 충분해지는 시점에만 해당 단계의 제안을 OWNER에게 알리고 외부 발송은 Human Gate로 유지한다.

## 공통 원칙
- 제안서는 미리 준비한다.
- 제안 시점은 날짜가 아니라 Evidence Gate로 결정한다.
- 외부 발송/기관 접촉/가격 확정/계약은 OWNER 승인 전 수행하지 않는다.
- 병원·정부·지자체의 공식 제휴/도입 표현은 실제 허가/계약 전 사용하지 않는다.
- 모든 제안은 "문제 -> 실사용 증거 -> 개선 -> 기관 가치 -> Pilot -> 측정 KPI" 구조를 따른다.

## STAGE P0 — 여수한국병원 DEMO 제안
목적:
- 기존 배포 콩케어의 개선판을 병원 현장 데모로 보여주기
- 환자/보호자 사용성 검증

READY 조건:
- Patient Demo v1 완료
- 핵심 5개 Golden 시나리오 PASS
- 개인정보 수집 없음
- 접근성 Blocker 0
- 공식근거 없는 정책카드 0
- DEMO/테스트 표기 명확

제안서 구성:
1. 콩케어 한 줄 소개
2. 기존 환자 불편
3. 데모 화면
4. 병원에서 기대하는 효과
5. 테스트 범위
6. 개인정보/보안 원칙
7. 병원 측 부담이 거의 없는 Pilot 방법
8. 다음 단계

## STAGE P1 — 병원 CLOSED PILOT 제안
READY 조건:
- Closed Beta 완료
- 핵심과업 성공률 목표 >=90%
- 반복 불편 Top N 정리
- 수정 전/후 Evidence
- Critical/High 보안결함 0
- 정책오류 P0 0
- rollback 가능

제안 핵심:
- 환자 상담/복지 연결의 반복 업무 감소
- 환자·보호자의 정보 접근성 향상
- 비식별 수요데이터 제공
- 병원 전용 정책/퇴원연계/보호자 기능 Pilot
- 2~4주 Pilot KPI 제안

## STAGE P2 — 병원 PRO / 도입 제안
READY 조건:
- Hospital Pilot 실제 운영 Evidence
- 병원 직원 피드백
- 정책 최신성/오류정정 SLA 근거
- 관리자/RBAC/감사로그 준비
- 운영/복구/보안 문서 준비

제안 핵심:
- 직원 상담모드
- 병원별 관리자
- 지역/질환별 지원팩
- 정책 변경감시
- 비식별 운영대시보드
- 월/연 SaaS + 구축/유지보수 옵션

## STAGE G1 — 여수시/전남도 정책 Pilot 제안
READY 조건:
- 지역 사용자 데이터 충분
- 지역별 수요/실패/UNKNOWN/정책 Gap 리포트
- 최소 1개 기관/병원 Case Study
- 개인정보/집계기준 검토
- 정책 인사이트 샘플 리포트

제안 핵심:
- 지역 장애인 복지정책 통합안내
- 정책 도달성/정보공백/미충족 수요
- 정책 CMS/변경감지
- 접근성 개선
- Pilot 전/후 KPI 측정

## STAGE G2 — 전국/광역 확장 제안
READY 조건:
- 5개 이상 지역 Golden E2E
- 전국 구조/중앙정책/지역팩 운영
- 데이터 품질/신선도 지표
- 다기관 권한/감사/복구
- Public Beta Evidence
- 기관 인바운드/재문의 증거

제안 핵심:
- 전국형 생활지원/복지정보 인프라
- 지역 간 정책 Gap 비교
- 기관용 정책 인사이트
- 공통 플랫폼 + vertical pack 구조
- API/Data Pack

## STAGE P3 — 생활지원 통합플랫폼 제안
READY 조건:
- 콩케어 + 인접 Vertical 2개 이상 실제 검증
- Shared Core 재사용 Evidence
- 사용자 UX가 통합으로 악화되지 않음
- 병원/지자체 구매자가 통합패키지를 선호하는 Evidence

제안 핵심:
- 하나의 Shared Core
- 장애/고령/퇴원연계/보호자 등 Vertical Pack
- 병원/지자체 Console
- 정책/수요 Gap 분석
- 단일 계약으로 확장 가능한 기관 플랫폼

## OWNER 알림 규칙
제안 READY 조건이 충족되면:
- "지금 제안할 시점입니다"라고 알림
- 대상기관
- 제안 목적
- 근거 Evidence
- 기대효과
- 제안서 버전
- 아직 남은 리스크
- 발송/접촉 Human Gate
를 1페이지 이내로 정리한다.

아직 READY가 아니면 제안 시점을 억지로 당기지 않고 필요한 Evidence를 먼저 만든다.
