# 콩케어 전국 장애인 상용화 MASTER PRODUCT SPEC v1.0

STATUS: ACTIVE_BUILD_BRANCH
BRANCH: product/nationwide-commercial-v1
SCOPE: 대한민국 전국 / 전 장애유형 / 고령자·보호자 포함
OWNER_INTENT: 누구나 직관적으로 쓰고, 실제 혜택을 놓치지 않게 하며, 공익성과 상용 지속가능성을 동시에 갖춘 전국형 장애인 생활·복지 AI 서비스

## 1. 제품 한 줄 정의
"내 조건에 맞는 복지·감면·의료·교통·주거·고용·교육·문화·긴급지원을 3초 안에 보여주고, 어디로 가야 하는지까지 바로 연결하는 전국 장애인 생활도우미"

## 2. 기존 자산 보존
- 기존 PWA/홈화면 설치 구조 유지
- 큰 글씨·단순 버튼·공식기관 Direct 링크 원칙 유지
- 하단 설치/공유/QR 묶음은 페이지 최하단 배치
- 정책·뉴스는 긴급복지와 분리, 필요 시 5~10개
- 공식기관 원문을 Source of Truth로 사용
- 기존 신장장애/투석 특화 콘텐츠는 "신장·투석 전문팩"으로 보존
- 여수 우선 설계는 "지역팩/시범지역"으로 보존하되 전국 기본값으로 확장

## 4. 핵심 UX
첫 화면은 4개 대형 버튼:
- "내가 받을 수 있는 혜택"
- "지금 급해요"
- "말로 물어보기"
- "지역 선택"

3탭 안에 결과 도달.
각 카드에는:
- 한 줄 요약
- 받을 가능성: 확인필요/조건부/높음 (법적 확정 표현 금지)
- 예상 금전/횟수/감면
- 신청 장소
- 준비물
- 마감/상시
- 공식 출처
- 전화/길찾기/공식사이트
- "내 체크리스트에 저장"

## 5. 접근성 기본
- 스크린리더 라벨/초점순서
- 키보드·스위치 접근
- 텍스트 확대 200% 이상 대응
- 색만으로 상태 전달 금지
- 충분한 명도 대비
- 최소 터치 타깃 48px 권장
- 자막/텍스트 대체/수어 확장 슬롯
- 음성명령/음성읽기
- 쉬운 글 모드
- 한 화면 한 과업
- 진동/소리/화면 알림 다중 제공
- 모션 최소화 옵션
- 보호자/대리 사용자 모드
- 인지·발달장애 사용자를 위한 단계형 안내

## 6. 개인화 원칙
V1: 로그인 없이 지역·관심영역·장애유형을 기기 안에만 저장.
V2: 계정은 선택사항. 민감정보 최소수집.
장애/건강 정보는 민감정보로 취급하고 목적·보유기간·동의·삭제 경로를 명시.
개인정보가 없어도 핵심 기능 사용 가능해야 함.

## 7. 데이터 계층
NATIONAL -> PROVINCE -> CITY/COUNTY -> DISTRICT -> PROGRAM
각 정책 레코드:
- source_url
- source_org
- effective_from/to
- region_scope
- disability_scope
- eligibility
- benefit
- application_method
- documents
- contact
- last_verified_at
- verifier
- status: ACTIVE/CHANGED/EXPIRED/UNKNOWN
- evidence_hash

공식 원문 우선순위:
법령/고시 > 중앙부처 > 지자체 > 공공기관 > 기타
블로그/카페/영상은 탐지 신호일 뿐 최종 근거 금지.

## 8. AI 기능
- 자연어/음성 질문
- 질문을 지역/장애/연령/소득/상황 조건으로 변환
- 근거가 있는 혜택만 답변
- 모르면 UNKNOWN/기관확인
- 의료진단/법률확정/수급확정 금지
- 답변마다 출처·기준일 표시
- 위험/긴급 상황은 119/112/129 등 공식 경로 우선

## 9. 상용화 모델
공익 핵심기능은 무료 유지.
수익화 후보는 사용자 혜택을 막지 않는 B2B/B2G 중심:
- 지자체/복지기관용 정책관리 대시보드
- 병원/복지관/기관용 상담지원
- 기관용 지역정책 API/데이터 품질 서비스
- 접근성 감사/도입 지원
광고로 핵심 혜택 노출 순위를 왜곡하지 않음.
민감정보 판매 금지.

## 10. 보안/프라이버시 P0
현재 공개 프론트엔드의 하드코딩 관리자 PIN은 상용화 이전 제거.
관리자 기능은 서버 인증 + 역할기반 권한 + 감사로그로 이전.
Secrets/API keys는 클라이언트/공개 Git에 저장 금지.
정책 수정은 draft -> review -> publish 2단계 이상.
외부 링크/콘텐츠 XSS·open redirect 검증.
민감정보 최소수집, 암호화, 보존기간, 삭제, 침해대응 절차 필요.

## 11. 상용화 품질 Gate
A. 접근성 자동검사 + 실제 보조기기 사용자 테스트
B. 전국 정책 데이터 정확도/신선도
C. 정책 변경 탐지와 rollback
D. 개인정보/보안 점검
E. 3G/저사양/큰글씨/스크린리더/키보드 테스트
F. 5개 이상 지역 Golden E2E
G. 장애유형별 대표 사용자 시나리오 검증
H. 운영자 CMS/감사로그
I. 장애/오류 복구
J. 법적 고지/이용약관/개인정보처리방침

## 12. 성공 KPI
- 첫 혜택 도달 중앙값 <= 30초
- 핵심과업 3탭 이내
- 공식근거 없는 정책 노출 0
- 변경/폐지 정책의 잘못된 ACTIVE 표기 0 목표
- 접근성 Blocker 0
- 사용자 과업성공률 >= 90% (실사용 테스트)
- 정책 카드 출처/기준일 표시율 100%
- 핵심기능 비로그인 사용 가능
