# 콩케어 성장·기관 인바운드 전략 v1.0

STATUS: ACTIVE_DIRECTION
GOAL: 개인 사용률을 높이되 핵심 기능은 무료로 유지하고, 사용성과 공익 데이터를 근거로 병원·지자체·정부·복지기관이 먼저 문의·제안을 보내는 구조를 만든다.

## 1. 성장 원칙
- 사용자 획득과 기관 영업을 분리하지 않는다.
- 개인 사용량 자체보다 "실사용 증거"를 쌓는다.
- 광고는 공익성/신뢰를 해치지 않는 범위에서만 쓴다.
- 유료광고보다 병원·복지관·지자체·환자회·커뮤니티 배포를 우선한다.
- 기관 문의는 별도 B2B/B2G 랜딩과 제안자료로 즉시 전환한다.
- 민감정보/개인정보를 리드 생성 목적으로 활용하지 않는다.

## 2. 사용자 성장 퍼널
AWARENESS
-> USE
-> VALUE
-> SHARE
-> RETURN
-> INSTITUTIONAL PROOF

### Awareness 채널 우선순위
1. 병원 현장 QR / 원무·사회복지·간호 안내
2. 복지관·장애인단체·환우회·보호자 커뮤니티
3. 지자체 복지부서/행정복지센터 안내물
4. 네이버/다음 검색형 콘텐츠
5. 블로그/카페/유튜브 정보형 콘텐츠
6. SNS 짧은 카드/영상
7. 필요할 때만 소액 검색광고

### Viral/Share
- "내 지역 혜택 보기" 딥링크
- 가족/보호자 공유
- 병원/복지관용 QR
- 카카오톡 공유
- 지역팩 공유
- 특정 지원정책 카드 공유

## 3. 기관 인바운드 퍼널
PUBLIC PRODUCT
-> LIVE METRICS
-> CASE STUDY
-> INSTITUTION PAGE
-> DEMO REQUEST
-> PILOT PROPOSAL
-> CONTRACT

기관이 홈페이지에서 60초 안에 확인할 것:
- 콩케어가 무엇인지
- 사용자에게 어떤 가치가 있는지
- 병원/지자체에 어떤 효과가 있는지
- 실제 이용/과업 성공/정책 신선도
- 보안/개인정보/접근성 원칙
- 데모/파일럿 요청 방법

## 4. 기관용 랜딩페이지 필수 섹션
1. "장애인이 필요한 복지정보를 30초 안에"
2. 환자/시민 화면 Demo
3. 병원/지자체 문제
4. 콩케어 해결 방식
5. 실사용 지표
6. 정책 인사이트 예시
7. 보안/개인정보/접근성
8. 여수한국병원 Demo/Case (허가된 사실만)
9. 도입 방식: DEMO -> PILOT -> PRO
10. 문의/제안 버튼

## 5. Contact CTA
- "기관 데모 요청"
- "병원 파일럿 문의"
- "지자체 정책분석 문의"
- "제휴/공공사업 제안"
- "자료 다운로드"

초기에는 메일/폼 중 하나로 단순화.
스팸·민감정보 유입을 줄이기 위해:
기관명 / 담당부서 / 업무용 이메일 / 문의유형 / 간단한 내용만 받고,
민감한 환자정보는 입력하지 말라는 고지.

## 6. 사용률 KPI
North Star:
- 주간 "도움 경로 도달" 수
보조:
- 첫 혜택 도달률
- 30초 내 과업 성공률
- 재방문율
- 공유율
- 지역팩 이용률
- 공식링크 클릭률
- 검색 실패율
- UNKNOWN 비율
- 피드백 완료율

Vanity metric 금지:
- 단순 페이지뷰만으로 성공 판단하지 않음.

## 7. 기관 신뢰 KPI
- 누적 사용 세션
- 핵심 과업 성공률
- 정책카드 공식출처율
- 정책 최신성
- 지역 커버리지
- 접근성 Blocker
- 정책오류 수정 SLA
- 병원/복지기관 Pilot 수
- 정책 개선 제안 수
- 기관 재문의/확장률

## 8. 기관이 먼저 연락하게 만드는 자산
- 월간 "장애인 복지 수요 인사이트 리포트"
- 지역별 정책 Gap Map
- 병원 환자지원 상담 Top10
- 정책 오정보/사각지대 리포트
- 접근성 개선 지표
- Demo video/interactive demo
- 1-page 기관 소개서
- 10-slide 제안서
- Case Study
- Security/Privacy sheet
- Accessibility conformance sheet

## 9. PR/콘텐츠 전략
콘텐츠는 광고보다 문제해결 중심:
- "여수 장애인이 놓치기 쉬운 지원 5가지"
- "투석환자 교통지원 신청 1분 요약"
- "장애인 복지정책, 왜 있어도 못 쓰나"
- "콩케어 데이터로 본 지역별 정보 사각지대"
- "병원 사회복지 상담을 더 빠르게 만드는 방법"

기관 담당자가 검색했을 때 제품보다 "문제 해결 능력"을 먼저 보게 한다.

## 10. 광고 원칙
초기 1순위 아님.
먼저 organic/partner distribution으로 product-market evidence를 만든다.
유료 광고를 쓰면:
- 검색의도 높은 키워드만
- 랜딩당 목표는 설치가 아니라 "도움 경로 도달"
- CAC를 사용자당 수익이 아니라 기관 인바운드 기여로 측정
- 건강/장애 민감타겟 추정 광고는 사용하지 않음

## 11. 기관 제안 자동화
EVENT:
- 특정 병원/지역에서 이용량 임계치
- 기관 도메인에서 반복 접근
- 데모 요청
- 정책 오류/수요 Gap 누적

AUTO PREP:
- 기관용 맞춤 1-page
- 해당 지역 사용지표
- 해당 기관 관련 정책 Gap
- Pilot 범위
- KPI
- 일정
- 비용 범위 초안

HUMAN GATE:
- 실제 외부 연락/제안서 발송
- 가격 확정
- 계약/제출

## 12. 90일 Growth 목표
Week 1-2:
- 병원 Demo
- 기관 랜딩
- QR/Share
- Feedback loop
- Analytics baseline

Week 3-4:
- 여수/전남 배포 파트너 5곳 후보
- 첫 Case Study
- 첫 월간 인사이트 리포트

Month 2:
- 기관 문의 3건 이상 목표
- Pilot 후보 1~2곳
- 지역별 수요 리포트

Month 3:
- 지자체/병원 제안 가능한 Evidence Pack
- 반복 가능한 병원/지자체 영업 패키지
- inbound -> demo -> pilot conversion 측정

## 13. 성공 조건
사용자가 무료로 도움을 얻는 구조를 유지하면서,
기관이 "이 데이터를 우리 정책/상담에 쓰고 싶다" 또는
"우리 병원/지역에도 적용하고 싶다"고 먼저 문의할 이유를 만든다.
